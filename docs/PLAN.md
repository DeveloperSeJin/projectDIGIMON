# DIGIMON 계획서

## 진행 상황

> 이 섹션은 진행에 따라 갱신한다. 아래 1장부터는 계획과 결정 기록이다.

- 현재 단계: Phase 1 착수 전 (3D 그래픽스를 배우기 시작하면 착수)
- 학습 수준: C++·고등수학 입문
- 최종 갱신: 2026-10-16

## 1. 개요

애니메이션 《디지몬》의 "데이터로 이루어진 평행세계에서 자율적으로 살아가는 디지털 생명체"라는 설정을 연구 프로젝트로 옮긴다. C++로 3D 디지털 월드를 시뮬레이션하고, 그 안의 모든 객체를 agent로 만들어 서로 상호작용하게 하며, 최종적으로 유저와 디지몬 사이의 유대를 연구한다.

- 프로젝트명: DIGIMON
- 잠정 정식 명칭: Digital Interactive Generative Intelligence for Multi-agent Organism Networks (미확정)
- 운영: 게임 엔진 스터디와는 별도 저장소로 독립 운영한다.
- 착수: 3D 그래픽스를 배우기 시작하는 시점부터 환경(세계) 구축을 시작하고, 배우는 내용을 바로 적용하며 진행한다.

## 2. 목표

1. 스스로 굴러가는 3D 디지털 월드를 만든다.
2. 세계 속 모든 객체를 agent로 만들어, agent들이 환경·서로·유저와 상호작용하게 한다.
3. 유저와 agent(디지몬) 사이의 유대가 형성되고 행동에 영향을 주는지 연구한다.

## 3. 구조

| 구분 | 이름 | 내용 |
|---|---|---|
| 틀 | 세계 | agent들이 존재하는 3D 공간과 시간. 틱, 절차적 생성. 3D 표현 방식은 미정. |
| 개체 | Agent | 세계 속 모든 객체 (디지몬, 자원, 지형지물, 아이템 등). 구현 방식 미정. |
| 상호작용 | Agent ↔ 환경 | 세계(지형·바이옴·시간 등)를 지각하고 그 위에서 행동하는 것. 이동, 지형의 영향, 지형 변형 등. |
| 상호작용 | Agent ↔ Agent | agent끼리의 상호작용. 섭식, 전투, 소통 등. |
| 상호작용 | Agent ↔ 유저 | 유저(테이머)의 개입, 유대, 인터페이스. |

환경과 agent의 경계(예: 자원을 세계 데이터로 둘지 agent로 둘지)는 agent 설계와 함께 정한다.

## 4. 엔진 설계 원칙 (확정)

1. 시뮬레이션과 렌더링 분리. 코어는 헤드리스로 실시간보다 빠르게 돌 수 있어야 하고, 뷰어는 읽기만 한다.
2. 고정 타임스텝. 세계는 틱 단위로 진행된다.
3. 시드 기반 재현성. 난수는 세계가 소유한 시드 기반 RNG만 쓴다.
4. 3D 설계. 세계는 처음부터 3D로 설계한다. 시뮬레이션 코어의 공간·좌표·물리도 3D다.

빌드 환경: Modern C++, CMake, Git, SDL3, OpenGL.

## 5. 일정

### Phase 1 — 환경(세계) 구축

착수: 3D 그래픽스를 배우기 시작하는 시점.

- 세계의 3D 표현 방식 결정
- 3D 세계 공간과 고정 틱 루프
- 시드 기반 절차적 생성(지형·바이옴)
- 헤드리스 실행과 SDL3/OpenGL 3D 뷰어
- 세계 저장·불러오기
- 완료 기준: 같은 시드로 같은 세계가 생성되고, 헤드리스와 뷰어 모드 모두 실행된다.

### Phase 2 — Agent 설계 결정

- 7장의 미정 항목을 검토하고 결정한다.
- 후보안별 작은 실험으로 비용·성능·재현성을 비교한다.
- 완료 기준: agent 설계가 결정 로그에 기록된다.

### Phase 3 — 상호작용 구현

- Agent ↔ 환경 → Agent ↔ Agent 순서로 구현
- 완료 기준: agent들이 세계 안에서 스스로 행동하고 서로 영향을 주는 것을 관찰할 수 있다.

### Phase 4 — 유저와의 유대

- 유저가 세계에 개입하는 인터페이스
- 유대의 형성과 영향 관찰
- 완료 기준: 유저와의 상호작용이 agent의 행동에 반영된다.

## 6. 산출물

각 Phase마다 다음을 남긴다.

- 다른 환경에서 빌드·실행되는 저장소
- 실행 방법, 설계, 알려진 제한 사항 문서
- 시연 영상 또는 실행 화면

## 7. Agent 설계 — 미정

agent를 만드는 부분이 이 프로젝트의 핵심이며, 결정 로그에 확정되기 전까지 결정하지 않는다.

정해야 할 것:

- 내부 구현: 상태값 기반 / 규칙 / SLM / LLM / 혼합
- 객체 종류별로 구현을 다르게 둘지, 통일할지
- 표현 방식: ECS / 클래스 객체 / 기타
- 행동이 세계에 반영되는 방식과 규칙 검증 주체
- agent 간 통신 방식
- 추론 위치: C++ 코어 내 / 별도 프로세스
- 환경과 agent의 경계, 세계 공간 자체를 agent로 볼지
- 유저를 세계 안의 agent로 표현할지
- 진화(디지볼루션), 기억, 성격, 유대의 구현

검토할 쟁점:

- 비용과 규모: agent 수 × 추론 비용
- 추론 속도가 틱 간격보다 느릴 때의 처리
- SLM/LLM 출력의 재현성
- agent 출력이 세계 규칙을 깨지 않게 하는 장치
- 기억을 가진 agent의 기억 오염

참고 자료: JaxLife, Generative Agents (Park et al., 2023), Foragax, EnTT / flecs, CoGrid + Multi-User Gymnasium

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 3D를 배우면서 동시에 만들어 생기는 재작업 | Phase 1을 작은 단위로 나누고, 이해한 범위 안에서만 구현 |
| agent 추론 비용 폭증 | Phase 2에서 소규모 실험으로 먼저 측정 |
| 3D로 인한 연산 비용 증가 (공간 질의, 지각, 물리) | 공간 분할을 3D 기준으로 설계하고, Phase 2 실험에서 함께 측정 |
| 범위 확장 | 각 Phase의 완료 기준을 넘는 기능은 다음 Phase로 미룸 |
| IP 문제 | 종과 세계관은 오리지널로 제작 |

- 시뮬레이션·렌더링 분리, 고정 타임스텝, 시드 기반 RNG

- 게임 엔진 스터디와 별도 저장소로 독립 운영 (2026-10-16)
